# routing-and-mixer-sensitivity
Observable: a discrete decision inside the stack flips. Compare a transformed or quantized model with its source on the same tokens and count, per layer, how often the router's selected expert set differs. Small weight changes in the router matrix produce a changed selection. A changed selection substitutes one whole expert's output for another's. This is a discontinuous change that no per-module error measured on that expert describes. The same shape appears at any module whose output is multiplied into a path instead of added to it. The output of such a module can move further than its own weight error suggests.
How to see it on your own model: on identical token sequences, report per layer the fraction of positions whose router top-k set differs between source and candidate. Capture the router's pre-softmax scores and also report the margin distribution between the k-th and (k+1)-th score. The margin explains the flips, and you can read it from the source alone, before you build anything. For a multiplicative mixer or gate, record the relative change of the module's output next to the relative change of its weights. A ratio far above one marks the condition. Both are forward hooks. Establish the floor first: compare the source against itself under a different kernel or dtype and count the flips that produces. What is above that floor points at the build when nothing else in the arithmetic changed. A flipped selection is not by itself an error: two experts can produce nearly the same output. An exactly function-preserving transform can still flip a selection in finite precision, which is a precondition failure of that transform's identity check, not a phenomenon.
Cards: cond-awq-moe, cond-moe-expert-hessian, rot-hadamard-r1
