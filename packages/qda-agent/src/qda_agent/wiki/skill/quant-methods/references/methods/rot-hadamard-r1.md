# rot-hadamard-r1
Addresses: a few residual-stream channels with large magnitude force the group scale of every reader (q/k/v/gate/up/router/lm_head input columns, linear-attention and expert input projections) to cover them, so the other channels of that group are rounded coarsely. Measured as: per residual channel, mean |h| over calibration text; per group of every reader's input columns, absmax/rms.
Mechanism: Fold every RMSNorm gain into the Linears that read the residual stream. Then carry the stream rotated, h -> hQ, with Q orthogonal: embedding E -> EQ, readers W -> W diag(g) Q, writers (o_proj, down_proj, linear-attention out_proj, expert down projections, any head that writes the stream) W -> QᵀW and b -> bQ. A unit-gain RMSNorm commutes with Q, so the function is unchanged in exact arithmetic. Every residual channel is spread over every quantization group of the readers' input columns and the writers' output rows. Q is a random-sign Sylvester Hadamard when the width is a power of two; otherwise Q is a Kronecker product of a small Hadamard of order 12, 20, 28, 36, 40, 52, 60, 108, 140, 156 or 172 (QuaRot's get_hadK) and a Sylvester block. The result is an ordinary bf16 checkpoint of the same architecture, which any quantizer then quantizes.
Effect: per-group absmax/rms of every reader's input columns and every writer's output rows falls toward that of a Gaussian group of the same width; the function is unchanged in exact arithmetic, but in the stored dtype the outputs and a top-k selection near a tie can still move.
Preconditions: a width that is a power of two or has a Kronecker factorisation with a known small Hadamard; RMSNorm without mean subtraction, plain (x·w) or zero-centred (x·(1+w)) gain, foldable into every reader; the full reader/writer set enumerable from the module tree, not from name patterns -- on a mixture-of-experts layer the router (which may not be an nn.Linear), the shared expert and every routed expert; on a hybrid stack the fused input projections and output projection of each linear-attention or gated-delta block; vision or multi-token heads that read or write the stream; a merger that replaces stream entries instead of adding to them; tied embedding/lm_head must be untied (the final-norm gain goes into lm_head only); do not serve a rotated checkpoint with an unrotated speculative or multi-token head.
Inference overhead: none (fully absorbed; same tensor names and shapes).
Pitfalls: a Sylvester construction exists only for a power-of-two width; at other widths use a Kronecker product with a small Hadamard of another construction, or a random orthogonal matrix. Do not pad, because padding changes the shapes the kernels expect. Second: mean-centering the embedding is not an RMSNorm identity (rms(x - mean(x)) is not rms(x)), so the identity check fails for a reason unrelated to the rotation; leave it off. Third: each fold or rotation stage in the stored dtype adds one rounding, which can look like an algebra error such as a missed reader; computing in a wider dtype and writing back once leaves one rounding. Fourth: an expert's input projections and the shared expert must take the same Q, and each expert's output projection takes Qᵀ independently. An error on one expert does not show in the logits of a short prompt if the router does not select that expert. Fifth: a rotated base that is not the same function as the source is a precondition failure of this method, not an observation about rotation. Sixth: a norm whose weight is all ones hides a missed fold, so do not check the fold only on such norms.
Origin: Ashkboos et al. (QuaRot) started from a few residual-stream coordinates with large magnitudes and from the invariance of the network under a consistent orthogonal change of the residual basis. A randomized Hadamard mixes every coordinate into every other before rounding, and between two learned matrices it is multiplied into the weights offline.
Source: Ashkboos et al., "QuaRot: Outlier-Free 4-Bit Inference in Rotated LLMs", NeurIPS 2024. https://arxiv.org/abs/2404.00456 · code: https://github.com/spcl/QuaRot
