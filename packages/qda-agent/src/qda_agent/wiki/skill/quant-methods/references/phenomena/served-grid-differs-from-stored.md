# served-grid-differs-from-stored
Observable: the weights the kernel computes with are not the weights the checkpoint stores. Dequantize a module the way the serving path does, including every conversion the loader applies to the scales. Compare the result with dequantizing it the way the producer assumed. The two differ uniformly across a group or a row. The difference is a property of the storage format, not of any rounding the producer priced.
How to see it on your own model: reconstruct one module's weights from the checkpoint's packed codes and scales twice, with the scales as stored and after the loader's own conversion. Read the conversion out of the serving code; do not infer it from the dtype name. Compare the two reconstructions and look at the per-group ratio. A conversion that is an identity gives exactly ones. Where activations are quantized, round a calibration batch the way the kernel rounds it and compare it with the raw batch. Both checks are offline and need no GPU. The phenomenon is present when either comparison is not an identity. The size of the difference is the size of an error term the producer never saw. If the grid a calibrated solver was given is not the grid that will be used, the compensation it computed is a compensation for a different problem. This is a per-format property, so it can be absent from one serving path and present in another for the same checkpoint.
