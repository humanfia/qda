# ill-conditioned-calibration-hessian
Observable: the calibration Hessians of a model's modules differ in conditioning. Normalise each module's H by its sample count and take the ratio of its largest to its smallest eigenvalue. A module's smallest eigenvalue can sit near the precision floor. In those modules a damped factorisation is numerically marginal. There, the solver's update, which multiplies by the inverse, is largest along the directions the calibration constrains least.
How to see it on your own model: during one calibration pass, keep each module's accumulated H and compute the eigenvalues of the normalised, symmetric matrix. Report per module the condition number, the smallest eigenvalue relative to the mean diagonal, and the number of calibration tokens the module saw. Plot the condition number against depth and against module type. The phenomenon is present when the spread across modules is wide. The token count tells you if a module is badly conditioned or only under-sampled; the condition number alone shows both the same way. A large condition number is not damage and does not predict it. One global damping constant regularises modules of different conditioning by different relative amounts, and a module that silently fails to factorise does not announce itself in the checkpoint.
