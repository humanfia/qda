# local-objective-vs-model-output
Observable: the quantity the solver minimises and the quantity you care about move independently. Two builds of the same format can be ordered one way by their summed per-layer calibration-Hessian energy. They can be ordered the other way by how far the whole model's output has moved from its source on the same text. A change that lowers the first quantity on every module can leave the second where it was.
How to see it on your own model: build two variants that differ in one knob of the local objective (damping, observer, feedback range, token weighting). For each, record the solver's own reported per-module loss. Separately, run both models and the source on the same text and record a divergence between the full next-token distributions, position by position. Plot one against the other per module and in total. No task data is needed: the source model is the reference. The phenomenon is present when the two orderings disagree, or when the per-module improvements are large and the model-level agreement barely moves. The local objective is a surrogate with a known gap: it is quadratic, per module, evaluated at the unquantized weights, and computed on one activation distribution.
