# grid-clip-search
Addresses: one outlier sets a group's range and leaves the other weights on a coarse grid. Measured as: per group, absmax/rms and the (channel-weighted) rounding error under the min/max grid.
Mechanism: Before quantization, the search tries a set of shrink factors below each group's min/max and keeps the (scale, zero) with the lowest weighted rounding error. Variants differ only in the weight of each input channel j: uniform with an |w−q|^p norm (`mse` observer), E[x_j²] from calibration (`imatrix_mse`), or the Hessian diagonal H_jj (`hmse`); `minmax` never clips. The shrink range (maxshrink) limits how much the search may clip.
Effect: per group, the channel-weighted rounding error of the chosen grid is at most the min/max grid's error (the unshrunk grid is a candidate); where a shrink is chosen, the step size falls and the error of the clipped entries rises.
Preconditions: none structural; the activation-weighted variants need calibration statistics.
Inference overhead: none.
Pitfalls: the grid is chosen on the original weights, before the compensating solver rewrites them, so the clip fits a tensor that is not the one finally rounded; this is a property of the schedule, and the in-solve forms remove it. Second: the activation-weighted observers need the calibration statistic reduced across all processes before the observer runs; otherwise each rank clips against its own shard's E[x^2], and the saved codes depend on the calibration partition. Third: if no group reaches the search floor, the shrink range is not binding; if a large fraction of groups sit exactly at the floor, it is binding; both are build-time diagnostics that the checkpoint does not show.
Origin: Shao et al. (OmniQuant) observed that a min/max scale is decided by the two most extreme weights of a group, so one far-out weight widens the step for every other weight in it, and made the clipping fraction a fitted parameter (lptq-omniquant).
