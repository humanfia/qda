# grid-served-scale
Addresses: the kernel re-rounds the stored group scales at load (for example to an e4m3 value times a per-row factor), which adds a per-group error the producer did not price. Measured as: per group, the ratio between the stored scale and the scale after the loader's own conversion, and the layer-output error that difference causes.
Mechanism: The W4A8-FP8 CUTLASS path converts the stored bf16 group scales at load to an e4m3 value times a per-row fp32 factor. The method snaps every group scale to that served grid before the codes are chosen, so RTN/GPTQ round and compensate against the scale the kernel multiplies with. Optionally, it chooses among the few nearest served-grid scales per group by input-weighted rounding error.
Effect: the scale the solver rounds and compensates against equals the scale the kernel multiplies with, so the stored-to-served ratio is exactly one and the uncompensated layer-output error from the conversion goes to zero.
Preconditions: a serving path whose scale storage differs from the checkpoint's (W4A8-FP8 CUTLASS, sym only); not used by the W4A16 Marlin path, which keeps bf16 scales.
Inference overhead: none.
Pitfalls: re-rounding the scales of a finished checkpoint is a different method from snapping them before the solve, except for round-to-nearest-like parents. An algorithmic parent chose its codes against the original scales, so new scales remove its compensation. Second: a scale folded through a conditioner cannot be transplanted, because the compensating factor is in another module. Third: if the producer's copy of the kernel's scale conversion is wrong, the build is priced against a grid the kernel does not use, and offline checks do not show the error. Compare dequantized weights against what the kernel computes.
Source: engineering: the producer reproduces the W4A8-FP8 kernel's own load-time scale conversion, no publication.
