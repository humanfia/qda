# local-damage-is-not-repair-value
Observable: the modules that carry the most local output-error energy are not the modules whose repair moves the model's output the most. Take a quantized base and a donor build of the same scheme whose whole-model output is closer to the source's. Take one group of modules at a time from the donor into the base. Set what each swap closes of the gap to the source beside the share of the base's local error energy that group carried. The two orderings can disagree, and not by a constant factor. A small projection can return a large share of the gap with a small share of the energy; a large one can hold much of the energy and return little.
How to see it on your own model: take one whole group of modules from the donor into the base and read the spliced checkpoint's output distance to the source on fixed text. The value of a swap is a product, not a size. To first order, the change of a whole-model output divergence L when module m goes from W to W' is the inner product of dL/dy_m with (W' - W) x_m. The first factor is how sensitive the divergence is to that module's output. The second factor is the output change the swap makes on the module's real input inside the assembled model. Local error energy measures only the size of the second factor, not the first factor or the angle between the two. Swaps can interact, so their values need not add up or scale with parameter count. Both factors come from one forward and one backward pass with a pass-through hook on every quantized linear, so no weight gradient is formed. The first-order value at the base alone can misstate a group's value, because the divergence is curved along the swap path. Take that pass at the base and again with every module taken from the donor, and average the two ends. This is exact to second order along the all-swap path. Check the two readings against each other on a few groups before you use either for your model and your pair. Both readings assume the two builds differ only inside the quantized modules; the swap is defined only for a whole fold unit (the norm with every module it feeds). A large repair value somewhere does not promise a mix whose output is closer to the source than both builds'. The product is a linearization, which needs three things to check on their own pair: units that act separably (a block trained end to end compensates inside itself, so part of it is not worth anything predictable), a well-conditioned backward (compare the tap with small-step finite differences, text by text), and no discrete switch in between (a routed model's changed expert selection is invisible to it). On a routed model an expert enters the output only at the positions routed to it, so its repair value per parameter is diluted by its routing fraction unless its per-token value is correspondingly larger.
