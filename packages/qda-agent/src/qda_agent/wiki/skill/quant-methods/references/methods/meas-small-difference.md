# meas-small-difference
Addresses: two builds of one source model can differ by less than the sampling noise of one sampled reading of each, so how a reading is built sets the smallest difference it can detect. Five properties of the reading set that floor: (1) whether the two builds are read on the same prompts and differenced per prompt; (2) whether sample j of a prompt uses the same sampler seed in both builds; (3) how many prompts sit where a small perturbation can flip the outcome; (4) whether an unfinished output is counted as a failed one; (5) whether the decision rule is fixed before the reading is seen. Measured as: for each prompt i of N, the difference d_i between the two builds' mean pass over their k samples of that prompt; the spread sd(d_i) across prompts; the per-sample outcome correlation rho between the two builds over (prompt, sample index) pairs; the reference's per-prompt pass rate p_i; per sample, whether generation stopped inside the output budget.
Mechanism: (1) Pairing: read both builds on the same N prompts with the same prompt rendering, sampling parameters and output budget, compute d_i per prompt, and report mean(d_i) with SE = sd(d_i) / sqrt(N); compare every candidate against one fixed reference on the same prompts, never as two separately computed means with two separate error bars. (2) Same seeds: give sample j of prompt i the same seed in every build (for example `seed = base + j`), with the base fixed before any build is read; an engine that seeds each request's sampler and draws its randomness step by step picks the same token in both builds wherever their next-token distributions are close enough, so the two generations stay together longer and their outcomes correlate. (3) Anchor pre-screen: on a pool of public training-set prompts with a checkable result, disjoint from the prompts the builds are finally read on and from the calibration set (drop exact duplicates and any long shared n-gram), sample an anchor model (the reference) k_s times per prompt with screening seeds and keep the prompts whose pass rate lies in a window fixed in advance (for example `[0.2, 0.8]`); save the kept list once per source model and output budget and reuse it unchanged for every build. (4) Separate counts: record per sample whether it finished (stopped inside the budget with the reasoning segment closed and a non-empty final part) and whether it passed (correct, or every constraint met by a deterministic checker that reads only the final part); pair the finished indicator and the pass indicator across builds separately. (5) Sample size and threshold fixed in advance: estimate from one pilot pair the within-prompt variance of a per-sample difference `s_w^2 = 2 p (1 - p) (1 - rho)` and the between-prompt variance `tau^2 = var(d_i) - s_w^2 / k`; plan with `SE(N, k) = sqrt((tau^2 + s_w^2 / k) / N)`; before generating, write down the prompt list, seeds, budget, N, k, the quantities reported, the smallest difference worth acting on `delta_min`, and the rule `|mean(d_i)| > z * SE` with z fixed (for example `z = 2`), and choose N and k so that `SE <= delta_min / (z + z_power)`, where `z_power` is the normal quantile of the detection probability wanted at `delta_min`; the cost per build is proportional to `N * k * (mean output length)`.
Effect: (1) the variance of mean(d_i) equals `(var_A + var_B - 2 cov_AB) / N`, so difficulty shared by both builds cancels and the SE of the paired difference shrinks by the shared part; (2) rho rises, and the per-sample difference variance `2 p (1 - p) (1 - rho)` falls with it; (3) the mean of `p (1 - p)` over the kept prompts moves toward its maximum at `p = 1/2`, and the share of prompts whose outcome a small perturbation can flip rises, so the N needed for a given SE falls; (4) the pass rate equals the finished rate times the pass rate among finished samples, so a change splits into a finished-rate term and a conditional term that are read separately; (5) at fixed k the SE falls as `1/sqrt(N)`, more samples per prompt shrink only the `s_w^2 / k` term, and once `tau^2` dominates the SE stays where it is under more samples and falls only with more prompts; the false-positive rate per comparison is bounded by the normal tail mass beyond z.
Preconditions: both builds can be served by one engine version with one batch layout and seeded per-request sampling; every prompt has an automatic check (a verifiable result, or constraints a program can check such as length, format, keyword, casing or section count); a reference build that every candidate is compared against; a pool of prompts disjoint from the prompts the builds are finally read on; a pilot pair large enough to estimate `s_w^2`, `tau^2` and rho.
Inference overhead: none on the served model; the reading costs `N * k` generations per build, plus `k_s` screening generations per pool prompt for the reference once per source model and output budget.
Pitfalls: (1) a request that fails (engine error, timeout, checker exception) is unmeasured, not a fail; drop it for both builds and report the count, since dropping it on one side only breaks the pairing; two single-build error bars combined as if independent overstate the noise of a paired reading, so overlapping bars say nothing about a paired difference. (2) once two token streams diverge the shared seed aligns only by position, so rho decays with generation length; batch composition and non-deterministic kernels can make one build differ from itself under one seed, so bound rho on one build (two reads with the same seeds give its ceiling, two reads with different seeds give its floor); change the engine, its version or the batch layout only between whole readings, never between the two builds of one comparison. (3) if the reference's measurement samples are the samples that selected the prompts, its reading sits nearer the window's middle than its real pass rate (regression to the mean) and every candidate-minus-reference difference carries that offset, so measure with seeds disjoint from the screening seeds; the window is set by the reference, so the kept list fits builds close to it; with small k_s, prompts whose true rate is near zero or one enter the window by chance. (4) when output budgets differ between the two builds, or a build finishes less often under a shared budget, the difference in unfinished share appears directly as a difference in pass rate and can look like a large paired difference between builds whose finished outputs pass equally often; compare builds only at one budget, report the finished rate beside the pass rate, and note that a screen at a short budget reads finishing behaviour at that budget only; conditional pass rates are taken over different finished subsets and cannot be paired directly, so pair the unconditional pass rate and the finished rate and treat the conditional rate as a description. (5) the planning formula assumes independent per-prompt differences, and near-copies (one template, one source problem) count as fewer than N; a reference read with `K >> k` samples per prompt removes the reference's own within-prompt term but gives up the shared seeds for the extra samples, and it leaves a smaller per-sample difference variance than shared seeds on k samples only when `rho < 1/2`; reading, checking and adding samples until the threshold is crossed (optional stopping) breaks the false-positive bound, so fix N and k first or use a sequential test designed for it; with many candidates against one reference the largest difference is biased upward, so adjust z for the number of comparisons or re-read the chosen build on new seeds and a new prompt list; a threshold on the pass rate says nothing about the finished rate, so fix one rule per quantity reported.
Source: general statistics, no single method paper. Common random numbers: Glasserman and Yao, "Some Guidelines and Guarantees for Common Random Numbers", Management Science 1992. https://doi.org/10.1287/mnsc.38.6.884 ; clustered standard errors and paired differences for sampled model outputs: Miller, "Adding Error Bars to Evals: A Statistical Approach to Language Model Evaluations", 2024. https://arxiv.org/abs/2411.00640
