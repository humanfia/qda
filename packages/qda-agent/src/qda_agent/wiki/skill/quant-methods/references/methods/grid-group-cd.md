# grid-group-cd
Addresses: a single forward pass compensates each column only onto later columns. So the last groups of a layer carry the accumulated error, and later rounding invalidates the target of the first groups. Measured as: per layer, the objective tr((Ŵ − W) H (Ŵ − W)ᵀ) after the forward pass, and per group the decrease available from re-solving that group with every other group fixed.
Mechanism: QuantEase minimises tr((Ŵ − W) H (Ŵ − W)ᵀ) by cyclic coordinate descent over the columns. With every other column fixed, column j's optimum is W_j + Σ_{k≠j} (W_k − Ŵ_k) H_kj / H_jj; the method rounds it onto its group's grid and moves to the next column. One sweep visits every column, and the sweep repeats a fixed number of times. Each group's (scale, zero) is set once from the original weights and does not change. A variant not in the paper: after a column-wise solve, the method sweeps the groups again: it re-solves each group g against the optimum given the current codes of all other groups. With R = (W_hat - W_t) H the residual gradient, the optimal update for group g is W*_g = W_hat_g - R_g H_gg^-1. The grid choice and in-group solve of the first pass then re-choose the group's (scale, zero) and codes for that target. A row keeps the new group only when the exact objective drops, so the sweep can be repeated.
Effect: in the variant, the layer objective is non-increasing at every accepted update; codes, scales and zero points change only where a row's objective went down.
Preconditions: the solver keeps H (or H_gg and the residual) after the forward pass; the container's groups are independent (static contiguous groups, one stored scale each), so one group can be rewritten without the others; an exact objective evaluator, because acceptance is per row and per group.
Inference overhead: none.
Pitfalls: a cheap proxy that screens which groups to visit can skip groups whose update would lower the exact objective, because the proxy ranks groups in a different order. Second: with an asymmetric target, recompute the residual R against that target, not against W0; otherwise the sweep walks the solution back toward the local objective. Third: invert H_gg with the same damping as the forward solve; with a different damping, the update solves a different problem. The acceptance test and the update use different code paths, so check that the objective does not increase at any accepted update.
Source: Behdin et al., "QuantEase: Optimization-based Quantization for Language Models", 2023. https://arxiv.org/abs/2309.01885 · code: https://github.com/linkedin/QuantEase
