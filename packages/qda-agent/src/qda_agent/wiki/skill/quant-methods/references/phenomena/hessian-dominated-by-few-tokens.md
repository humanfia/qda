# hessian-dominated-by-few-tokens
Observable: at a module's input, a small fraction of the token positions holds most of the sum of squared activation norms over the calibration stream. So the matrix that every calibrated solver minimises against is, numerically, the matrix of those positions.
How to see it on your own model: hook one Linear's input over the calibration set you intend to build with, record ||x_t||^2 per token position, sort it descending and plot the cumulative share. This needs one forward pass and no build. The phenomenon is present when a small leading fraction of positions holds most of the total. Separate the positional part from the content part: take the same curve with the first few positions of every chunk excluded. Then repeat it on a second, differently-chunked pass over the same text. If the heavy positions move with the chunk boundaries, they are partly an artefact of how the stream was cut, which is a knob you control. This is a statement about the calibration matrix, not about which tokens matter. A high-energy token can be one the model is completely certain about, where an error may move the output little. A token the solver never sees cannot be compensated at all, whatever its importance.
